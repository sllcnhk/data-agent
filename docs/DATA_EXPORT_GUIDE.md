## 1. 30 秒决策表

先回答一个问题：**这份数据是给人看，还是给程序用？**

| 你的情况 | 模式 | 格式 | 还要填什么 |
|---------|------|------|-----------|
| 几万~几十万行，业务方要用 Excel 打开看 | 单文件 | **Excel** | 无 |
| 几十万~几百万行，喂给程序 / 再入库 | 单文件 | **CSV** | **游标列名** |
| 千万行级月明细，喂给程序（最常见） | **按日期分块** | **CSV ZIP** | 占位符 SQL + **游标列名** |
| 千万行级，要按时间段分别交付 | **按日期分块** | **CSV** | 占位符 SQL + **游标列名** |
| 跨境网络，经常 5 分钟断流 | **按日期分块** | CSV / CSV ZIP | **游标列名**（必填）+ 小 `单块天数` |
| 数据没有时间维度 / 需要聚合后导出 | 单文件 | 按上面两行选 | 聚合 SQL **不能**填游标列 |

**只记一条**：数据量超过百万行、或者网络不稳，就**填游标列名**。它是唯一能让「断流后从已下载位置继续」的开关。

## 2. 三种格式的真实差异

| | Excel (.xlsx) | CSV (.csv) | CSV ZIP (.zip) |
|---|---|---|---|
| 速度 | 最慢（要写 XML+ZIP） | **最快**（原始字节直通） | 最快 + 压缩耗时 |
| 分块模式下的产物 | N 个 .xlsx | N 个 .csv（逐个下载） | **1 个 .zip**（一次下完） |
| 每 100 万行分 Sheet | ✅ | ❌ 无 Sheet 概念 | ❌ |
| **数值列在 Excel 里的类型** | ⚠️ **全是文本** | 数值（Excel 自动推断） | 同 CSV |
| 大整数（Int64/UInt64） | 保留完整精度（因为是文本） | ⚠️ Excel 打开变**科学计数法** | 同 CSV |
| NULL 的表现 | 空单元格 | ⚠️ 字面量 **`\N`** | 同 CSV |
| 中文 | 原生支持 | UTF-8 BOM，Excel 打开不乱码 | 同 CSV |
| **断流可续传** | 仅填了游标列时 | 仅填了游标列时 | 仅填了游标列时 |

### 2.1 ⚠️ Excel 的所有单元格都是文本

这条最容易被投诉，先说清楚：**导出的 xlsx 里，每一个单元格都是文本**，包括数值列、日期列、小整数。业务方拿到后**不能直接求和、排序、做数据透视**（Excel 会显示绿色小三角）。

两条写入策略（`直接写 XLSX` / `先落 CSV 再转`）行为完全一致，**没有任何开关能改变这一点**。

规避方法（二选一）：

1. 拿到 xlsx 后，在 Excel 里选中目标列 → 「**数据 → 分列 → 下一步 → 下一步 → 完成**」，文本即转为数值
2. 改导 CSV，在 Excel 里用「**数据 → 从文本/CSV**」导入向导，逐列指定类型（大整数列要指定为**文本**，否则精度丢失，见 §2.2）

### 2.2 ⚠️ CSV 的大整数在 Excel 里会丢精度

CSV 是 ClickHouse 原始字节直通，`Int64` / `UInt64` 原样输出 20 位数字。**双击用 Excel 打开会变成 `1.84467E+19` 且末尾数位永久丢失。**

- 喂给程序 / 入库：**没有这个问题**，正常读取
- 一定要用 Excel 看：在 SQL 里 `toString(你的大整数列) AS xxx`，或用「数据 → 从文本/CSV」把该列指定为文本

### 2.3 ⚠️ CSV 的 NULL 是字面量 `\N`

ClickHouse 的 CSV 输出把 NULL 写成两个字符 `\N`（不是空字段）。**它对不同下游的含义不一样**（均已实测）：

| 下游 | `\N` 的表现 | 要做什么 |
|------|-----------|---------|
| **导回 ClickHouse**（`FORMAT CSVWithNames`） | ✅ 正确识别为 NULL | 什么都不用做 |
| pandas / 通用 CSV 解析器 | ⚠️ 字面字符串 `"\N"` | 显式声明缺失值 |
| Excel | 单元格显示 `\N` | 手动替换 |

```python
# pandas 读取 ClickHouse 导出的 CSV
df = pd.read_csv("export.csv", na_values=["\\N"])
```

XLSX 路径把 NULL 写成空单元格，两种格式表现不同 —— 同一份 SQL 换格式后下游解析逻辑可能要改。

## 3. 场景一：给人看的小数据量

1. 输入 SQL → 选连接 → 点「**查询预览**」（或 `Ctrl+Enter`），确认前 100 行结构正确
2. 点预览区右上角「**导出**」
3. 导出模式 `单文件`、输出格式 `Excel (.xlsx)`，其余不动

**看一眼 Modal 底部的「你将得到什么」**，它会实时告诉你这套配置的产物形态、NULL 表现、断流后会怎样。这段是后端按实际代码路径算出来的，不是固定文案。

## 4. 场景二：千万行明细喂程序（主路径）

### 4.1 先把 SQL 改成占位符写法

分块导出会把日期范围切成 N 段，每段单独跑一次查询。**推荐用占位符**让 ClickHouse 把日期条件下推到源表（性能最好）：

```sql
-- ✅ 推荐：ts 占位符（半开区间，day / sub-day 都兼容）
SELECT
    call_record_id,
    user_id,
    toString(amount_cents) AS amount_cents,   -- 大整数转文本，防 Excel 科学计数法
    call_start_time
FROM dwd.call_record
PREWHERE call_start_time >= parseDateTimeBestEffort('{{ts_start}}')
     AND call_start_time <  parseDateTimeBestEffort('{{ts_end}}')
  AND status = 'paid'
```

要点：

- `{{ts_start}}` 是**含**起点，`{{ts_end}}` 是**不含**终点（半开区间），所以用 `<` 而不是 `<=`
- 两个占位符**必须成对出现**，只写一个会被校验层拒绝（400）
- `parseDateTimeBestEffort` 同时兼容 `Date` / `DateTime` / `DateTime64` 列
- 还有一套老占位符 `{{date_start}}` / `{{date_end}}`（闭区间、day 模式输出 `YYYY-MM-DD`）。**如果你会用到「最小再细分粒度=小时/分钟」，必须用 `ts` 那套** —— 老占位符在 sub-day 下会导致同一天数据被取两遍（详见 §7.2）

如果不方便改 SQL，也可以不写占位符，改在配置里填「日期列名」，由系统外包一层过滤子查询。缺点是复杂查询（GROUP BY / JOIN）时条件无法下推，可能慢很多。

### 4.2 预览带占位符的 SQL

带占位符的 SQL 不能直接执行。系统会在预览时把占位符替换成一个「样本日期」：

- 出现提示框和「预览样本日期」选择器，留空默认用**昨日**
- ⚠️ 这个「昨日」是按 **UTC** 算的（`datetime.utcnow()`）。**东八区下留空实际取到的是前天**。想精确控制就手动选日期
- 预览表格标题会显示「占位符替换为 YYYY-MM-DD」，核对一下

### 4.3 配置

点「导出」→ 切到「**按日期分块（多文件）**」：

| 字段 | 填什么 | 说明 |
|------|-------|------|
| 输出格式 | **CSV ZIP** | 一次下完；要按时间段分别交付就选 CSV |
| 日期范围 | 如 2026-07-01 ~ 2026-07-31 | 闭区间，含起止日 |
| 单块天数 | **1~3** | 跨境网络建议 1；让单次查询 < 5 分钟 |
| 日期列名 | 留空 | SQL 已用占位符 |
| **游标列名** | **表 ORDER BY 键的前缀** | 见 §5，这是能否续传的关键 |
| 批次大小 | 默认 50000 | 填了游标列后它变成「每个 keyset 窗口的行数」 |

其余「最小再细分粒度」「预分裂窗口」是应对极端情况的高级项，见 §7。

### 4.4 监控与下载

- 「导出历史」每 2 秒自动刷新
- 进度列显示已完成块数 / 总块数，以及当前在跑哪一块
- CSV ZIP：完成后直接点下载图标
- CSV（非 ZIP）：点行左侧 `>` 展开，逐个下载子文件
- 状态 `部分完成`（橙色）：部分块成功、部分失败。**已成功的块可以正常下载**，失败的块点「重试」图标单独重跑，不影响已完成的

## 5. 游标列名怎么选（最重要的一节）

### 5.1 它解决什么问题

不填游标列时，CSV 导出是**一个长查询**。跨境 / 云上 LB 通常在 ~5 分钟空闲后切断连接，此时：

> 已经下载的几个 GB **全部作废**，整个导出失败，从零重来。

填了游标列后，导出变成**一串独立的短查询**（每个窗口 `WHERE 游标 > 上次末值 ORDER BY 游标 LIMIT N`）。某个窗口断流时：

1. 文件被精确截回**上一条完整记录**的位置（不会留半行残数据）
2. 从断点的游标值重发**同一个窗口**
3. 已落盘的数据一个字节都不丢

同时每个查询都短，对 ClickHouse 的压力也更平缓。

### 5.2 怎么选这一列

**必须满足**：

- **单调可排序** —— 主键、自增 ID、时间戳
- **非 NULL** —— 游标列出现 NULL 会直接报错终止（ClickHouse 默认把 NULL 排在最后，`WHERE 游标 > NULL` 恒为假，永远推进不动）
- **不能用于聚合 SQL** —— SQL 里有 `GROUP BY` / `DISTINCT` / `WITH ROLLUP` 时**不要填**

**强烈建议**：

> **选表 `ORDER BY` 键的前缀列。**

因为每个窗口都带 `ORDER BY 游标`。如果这一列正好是表排序键的前缀，ClickHouse 走 read-in-order，几乎零成本；**否则每个窗口都要真排序，压力可能比不填游标列还大**。

查表的排序键：

```sql
SELECT sorting_key FROM system.tables
WHERE database = '你的库' AND name = '你的表';
```

**填的是 SELECT 子句里的别名**，不是原表的 `表.列`。系统会把你的 SQL 包成 `SELECT * FROM (你的SQL) AS _ks_q`，外层只看得到别名：

| 你的 SQL 写法 | 游标列名填 |
|--------------|-----------|
| `cr.call_record_id AS call_record_id` | `call_record_id` |
| `cr.call_record_id AS \`Call ID\`` | `Call ID`（含空格，直接填，不用加反引号） |
| `cr.order_id AS 订单_id` | `订单_id` |
| `cr.call_record_id`（无别名） | `call_record_id`（ClickHouse 默认取最右段） |

允许字母 / 数字 / 下划线 / 空格 / 中文；**不能含反引号**（系统会自动加）。

### 5.3 填之前先自查

```sql
-- ① 游标列在结果集里吗（跑一次预览确认列名）
-- ② 有 NULL 吗？应该是 0
SELECT count() FROM (你的SQL) WHERE 游标列 IS NULL;
-- ③ 有重复值吗？重复过多会被死循环保护拦下
SELECT count() AS rows, uniqExact(游标列) AS uniq FROM (你的SQL);
```

### 5.4 它在哪些组合下生效

填了就一定生效 —— 但**作用不同**：

| 格式 / 策略 | 游标列的作用 |
|------------|-------------|
| CSV / CSV ZIP | 全程 keyset 多窗口，**断流可续传** |
| Excel + 先落 CSV 再转（分块模式默认） | CSV 落盘阶段 keyset 多窗口，**断流可续传** |
| Excel + 直接写 XLSX | 流式断开后用 keyset 代替 LIMIT/OFFSET 回退，消除重复 / 漏行 |

## 6. CSV 下游必读

ClickHouse 的 CSV 输出遵循 RFC4180（IDN 实测确认）：

```
"f_comma","f_quote","f_newline"
"a,b","he said ""hi""","line1
line2"
```

- 字段含**逗号**、**双引号**或**换行**时，整个字段被双引号包裹，内部的 `"` 转义成 `""`
- **一条记录可以跨多个物理行**（引号内的换行是数据）

所以：

| ❌ 不要这样 | ✅ 应该这样 |
|-----------|-----------|
| `line.split(',')` | 标准 CSV 解析器（`csv.reader` / `pandas.read_csv`） |
| `awk -F,` / `cut -d,` | `csvkit` / 程序里用 CSV 库 |
| `wc -l` 数行数 | 用 CSV 解析器数记录数 —— **含换行的字段会让 `wc -l` 偏大** |

导入回 ClickHouse 没问题（已实测往返无损，含逗号 / 引号 / 换行 / 20 位大整数 / NULL）：

```sql
INSERT INTO db.table FORMAT CSVWithNames  -- 直接喂导出的文件，POST body 传数据
```

制表符在 CSV 里**不转义**（原样输出），这点和 TSV 路径不同。

## 7. 高级项（只在被断流反复折磨时才需要）

### 7.1 最小再细分粒度

某个块反复失败时，系统会自动把它对半拆成更小的块重试。这个选项决定「最小能拆到多细」：

- `天`（默认）：拆到 1 天为止，1 天块还失败就放弃这块
- `小时` / `分钟`：1 天块失败后继续拆 12h → 6h → 3h…

**前提**：SQL 里过滤的那一列必须是 `DateTime` 类型。如果是 `Date` 类型，sub-day 的时间字面量会被 ClickHouse 截断到日期，拆出来的子块返回完全相同的数据，白拆一场。

### 7.2 ⚠️ 用 sub-day 就必须用 `ts` 占位符

老占位符 `{{date_start}}` / `{{date_end}}` 是**闭区间**，且 day 模式输出 `YYYY-MM-DD`、sub-day 模式输出 `YYYY-MM-DD HH:MM:SS`。这让同一份 SQL 无法同时正确处理两种模式：

- SQL 写 `addDays(toDate('{{date_end}}'), 1)`（day 模式正确）→ sub-day 时 `toDate('2026-03-01 11:59:59')` 被截断到 `2026-03-01`，**整天数据被两个 12h 子块各取一遍 → 数据翻倍**
- 改成 `addDays(parseDateTimeBestEffort('{{date_end}}'), 1) + INTERVAL 1 SECOND` → sub-day 时过滤窗口变成 36 小时，**与第二半子块严重重叠**

`{{ts_start}}` / `{{ts_end}}` 无论哪种模式都输出 datetime 字面量，且 `ts_end` 永远等于「下一个窗口的起点」，配合 `>=` 和 `<` 天然无重叠无遗漏。**sub-day 场景一律用它。**

### 7.3 预分裂窗口

启用小时/分钟级再细分后，系统默认在**开跑之前**就把每天预拆成 6 小时的窗口，省掉「先跑整天大查询、5 分钟后断流、再拆」的浪费。

- `固定小时数`：填 1~24，留空默认 6
- `自动（按数据量）`：先统计每小时行数，按「每窗口目标行数」（默认 100 万）自动切。数据量按小时波动很大时更合适，代价是多一次统计查询

### 7.4 首选分批模式

跳过「先试单流」直接走分批。**只对「直接写 XLSX」策略有效**，其他路径本来就不做单流首试，此开关会置灰。

### 7.5 批次大小

- 「直接写 XLSX」路径：每批从数据库读取的行数
- 填了游标列的 CSV / 先落 CSV 路径：**每个 keyset 窗口的行数**
- 其他情况：**不生效**（会置灰并说明原因）

## 8. 任务状态与操作

| 状态 | 含义 | 能做什么 |
|------|------|---------|
| 等待中 | 已排队，未开始 | 取消 |
| 导出中 | 正在跑 | 取消 |
| 已完成 | 全部成功 | 下载、删除 |
| **部分完成** | 分块模式下部分块成功、部分失败 | **下载已成功的块**、重试失败块、删除 |
| 失败 | 单文件失败，或分块模式全部块失败 | 看详情、重试失败块（分块）、删除 |
| 取消中 / 已取消 | — | 删除 |

### 8.1 ⚠️ 取消的语义按模式不同

- **分块模式**取消：已完成的块**保留且可下载**，未开始的块跳过
- **单文件模式**取消：**本次导出作废，不能下载**（下载接口只接受已完成的任务）。磁盘上可能残留一个不完整文件，点「删除」清理

需要「取消后保留已完成部分」的能力，就用分块模式。

### 8.2 重试失败子任务

只有分块模式有。点行上的重试图标，所有 `failed` 的块会**按原顺序串行重跑**，已完成的块不受影响。可以在弹窗里改批次大小（比原任务小一点往往更容易成功）。

### 8.3 删除

删除会**连带删除服务端文件**。分块任务会递归删掉整个输出目录。**下载完再删。**

## 9. 报错对照表

失败任务点「查看详情」可以看到可读说明 + 可复制的完整技术细节。

| 症状（错误信息里的关键词） | 原因 | 怎么办 |
|--------------------------|------|--------|
| `Connection broken` / `IncompleteRead` / `Response ended prematurely` / `ChunkedEncodingError` | 中间链路（云 LB / NAT / 代理）在 ~5 分钟空闲后切断了连接 | **填游标列名**启用续传；分块模式把「单块天数」降到 1~2；简化 SQL 里的高 CPU 运算 |
| `Code: 160` / `ESTIMATED_EXECUTION_TIMEOUT_EXCEEDED` | ClickHouse 估算这个查询太久，直接拒绝执行 | 缩小时间范围 / 改用分块模式；请 DBA 加索引或分区 |
| `Code: 202` / `Too many simultaneous queries` | ClickHouse 用户级并发查询数满了 | 系统会自动退避重试；仍失败就错峰，或减少同时跑的报表 |
| `keyset 分页失败：cursor 列 ... 为 NULL` | 游标列有 NULL 值 | SQL 里加 `AND 游标列 IS NOT NULL`，或换一个非空列 |
| `keyset cursor 死循环` | 游标列重复值太多，窗口推进不动 | 换主键列，或用「时间戳 + 唯一 ID」的复合列 |
| `cursor_column ... 未在 CSV 表头中找到` | 填的不是 SELECT 子句里的别名 | 按 §5.2 填别名 |
| `SQL 中 {{date_start}}/{{date_end}} 必须各自成对出现` | 占位符只写了一个 | 补齐另一个 |
| `chunk_config 校验失败` | 日期范围 / 单块天数 / 列名不合法 | 单块天数须 1~90；日期列名只允许字母数字下划线 |
| 下载时提示「任务尚未完成」 | 单文件模式取消或失败的任务不能下载 | 重新提交（见 §8.1） |

## 10. 已知限制

| 限制 | 说明 | 规避 |
|------|------|------|
| XLSX 所有单元格是文本 | 两条引擎行为一致，无开关 | Excel 内分列，或改导 CSV 用导入向导 |
| CSV 大整数在 Excel 里丢精度 | 原始字节直通 | SQL 里 `toString()`，或导入向导指定为文本 |
| CSV 的 NULL 是 `\N` | 与 XLSX 的空单元格不一致 | 下游 `na_values=['\\N']` |
| 不填游标列时 CSV 断流无救 | 单流没有回退也没有续传 | 填游标列 |
| 单文件取消 / 失败后不可下载 | 下载接口只接受已完成任务 | 用分块模式 |
| 预览「默认昨日」按 UTC 算 | 东八区实际是前天 | 手动选样本日期 |
| 聚合 SQL 不能用游标列 | `GROUP BY` 后行不在原表中，游标语义失效 | 不填游标列，改用小分块 |
| 单 Sheet 上限 100 万行 | 超出自动新建 Sheet（Excel 硬上限约 104 万） | 无需处理，自动的 |
| 单块天数 1~90 | 双层校验 | — |
| 同一连接同时只跑 1 个导出查询 | 防止挤爆 ClickHouse 并发上限 | 排队等待即可 |
| 系统级最多 4 个导出并发 | 线程池上限 | 排队等待即可 |

## 11. 最佳实践速查

**跨境 + 千万行明细 + 喂程序（本项目最常见的场景）：**

```
导出模式    按日期分块（多文件）
输出格式    CSV ZIP
SQL         用 {{ts_start}} / {{ts_end}} 半开区间占位符
            大整数列套 toString()
日期范围    按需
单块天数    1
日期列名    留空（SQL 已有占位符）
游标列名    表 ORDER BY 键的前缀列（务必核对）
批次大小    50000（= 每个 keyset 窗口行数）
```

这套配置下的行为链条：

1. 日期范围按天切块，逐块串行执行
2. 每块内部走 keyset 多窗口，每个窗口一个独立短查询
3. 窗口断流 → 文件截回上一条完整记录 → 从断点游标重发该窗口（默认最多 3 次）
4. 窗口级都救不回来 → 块级原位重试 1 次 → 再失败则对半拆块重试
5. 某块彻底失败 → **跳过它继续跑后面的块**，任务终态为「部分完成」
6. 事后对失败块点「重试」单独重跑，已完成的块不受影响

**要交给业务方用 Excel 打开时**，额外做两件事：SQL 里把大整数 `toString()`；告知对方数值列是文本，需要在 Excel 里分列。
